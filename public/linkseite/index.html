So baust du deine Link-Seite mit Claude Code

Meine Link-Seite ist ein iPod, mit Snake und einem eigenen Blockspiel. Ich hab keine Zeile Code davon getippt. Hier steht, wie Claude Code sie gebaut hat, mit drei Prompts zum Kopieren.

Bevor du anfängst

Du musst nicht programmieren können

Claude Code schreibt den Code, testet ihn und baut die Seite. Du sagst klar, was du willst, und legst fest, wann etwas gut genug ist. Die sieben Schritte unten zeigen, wie das bei mir lief.

Schritt 1

Ein echtes Ding als Vorbild

Damit deine Seite nach dir aussieht.

Warum ein Ding

Eine Link-Seite ist eine Liste mit Knöpfen. Ohne Vorbild sieht sie schnell aus wie jede andere. Ein echtes Gerät gibt Claude Code klare Regeln. Es hat Maße, eine Bedienung und Details, an denen man Fehler sofort sieht.

Ideen

  • Ein Gameboy, der Menü und Spiele zeigt
  • Ein Kassettenrekorder, bei dem jeder Link eine Kassette ist
  • Ein altes Tastenhandy mit SMS als Links
  • Ein Getränkeautomat, bei dem jeder Knopf einen Link ausgibt

Häufiger Fehler

„Bau mir eine coole Link-Seite.“ Mit so einem Satz muss die KI raten, was du mit „cool“ meinst.

Probier das

Schreib einen Satz: Meine Seite sieht aus wie ___ und man bedient sie wie ___.

Schritt 2

Der erste Prompt

Sagt Claude Code, was „fertig“ heißt.

Mein erster Prompt steckt in einer alten Sitzung. So würde ich ihn heute schreiben. Ersetz die gelben Stellen.

Prompt 1 · Der Brief
Bau mir eine Link-Seite, die aussieht wie [DEIN VORBILD].

Inhalt:
- Name: [DEIN NAME]
- Links: [Instagram-Link, TikTok-Link, YouTube-Link, E-Mail]
- Zwei Sätze über mich: [TEXT]

Bedienung:
- [Wie bedient man das Vorbild? Zum Beispiel: Rad drehen, Knopf drücken]
- Auf dem Handy genauso gut wie am Laptop.

Technik:
- Eine statische Seite für GitHub Pages.
- Alle Texte und Links in einer Datei, public/config.json. Ich will sie ohne Code ändern können.
- Alle Grafiken selbst gezeichnet. Keine fremden Bilder oder Logos.
- Schriften als Dateien auf der Seite, nicht von Google geladen.
- Ohne JavaScript erscheint eine einfache Linkliste.

Bevor du baust:
1. Leg ein Fundament an. Eine Datei mit allen Maßen und Regeln, und wer welche Datei bearbeitet.
2. Bau ein Werkzeug, das Screenshots der Seite macht.
3. Frag mich alles, was unklar ist.

Was das Fundament bringt

Bei mir legte Claude Code zuerst eine Datei mit allen Maßen des iPods an. Das 3D-Intro und der iPod auf der Seite lesen beide daraus. Deshalb passt das Intro am Ende genau auf die Seite, auf 0,01 Pixel.

Schritt 3

Das Turnier

Aus einem Glückstreffer wird eine Auswahl.

So lief es bei mir

  1. Claude Code baute zwei Versionen gleichzeitig, A und B.
  2. Drei KI-Richter bewerteten beide. Jeder Richter hatte ein Thema: Echtheit, Bedienung, Technik.
  3. A gewann 2:1. Aber der Schnitt lag bei 7,13, und die Latte bei 7,5. Keine war gut genug.
  4. Also baute Claude Code eine dritte Version, C, aus der ganzen Kritik. C schlug A mit 3:0.
  5. Im Finale baute ein zweites KI-Modell seine eigene Version. Diesmal kam jeder Richter von einem anderen Modell. C gewann wieder 3:0.
  6. Danach kamen Ausbesserungsrunden mit festen Mängellisten. Eine unabhängige Prüfung fand am Ende 0 offene Fehler.
Prompt 2 · Das Turnier
Bau zwei Versionen von [TEIL, zum Beispiel dem Startbildschirm] gleichzeitig, jede in ihrem eigenen Ordner.

Dann lass drei Richter beide Versionen bewerten. Jeder Richter prüft ein Thema:
1. Echtheit: Sieht es aus wie [DEIN VORBILD]?
2. Bedienung: Fühlt es sich richtig an, auf dem Handy und am Laptop?
3. Technik: Lädt es schnell? Gibt es Fehler?
Die Richter sehen Screenshots, nicht nur den Code. Punkte von 1 bis 10, mit Begründung.

Die Latte liegt bei 7,5 im Schnitt. Schafft das keine Version, bau eine dritte aus der ganzen Kritik. Lass sie gegen die bessere antreten.

Behalt nur die Siegerin und lösch die anderen. Dann bessere sie aus, bis ein frischer Prüfer keine Fehler mehr findet.

Warum das klappt

Eine Seite bewerten ist leichter, als sie zu bauen. Zwei Versionen zeigen, was geht. Die Kritik daran zeigt, was fehlt. Version C war bei mir die erste, die auf all dieser Kritik aufbaute.

Was es kostet

Ein Turnier braucht ein Vielfaches an Nutzung. Mit Pro kann es sein, dass du zwischendurch auf dein Limit wartest. Fang mit einem Teil an, zum Beispiel dem Startbildschirm.

Probier das

Leg die Latte fest, bevor du die Ergebnisse siehst. Sonst nimmst du die erste Version, die halbwegs passt.

Schritt 4

Prüfrunden

Finden, was im Turnier niemand gesehen hat.

Um 22:58 setzte Claude Code die Sieger zu einer Seite zusammen. Dann liefen drei Prüfrunden durch die Nacht. Am nächsten Vormittag war die Seite online.

Was die Prüfrunden fanden

  • Zu wenig Kontrast bei kleinen Texten
  • Ein Tipp auf den Mittelknopf zählte manchmal doppelt
  • Mit der Tastatur ging nach einem Klick der Fokus verloren
  • Auf dem Handy im Querformat war der iPod schlecht lesbar
  • Auf langsamen Geräten ruckelte das Intro
  • Links in der Config wurden zu wenig geprüft
Prompt 3 · Prüfrunde
Prüf die ganze Seite wie ein strenger Prüfer, der sie zum ersten Mal sieht.
Teste: Handy hoch und quer, ein langsames Gerät, nur Tastatur, Screenreader, ohne JavaScript, ein kaputter Link in der Config.
Sortier die Funde nach hoch, mittel und niedrig. Beheb hoch und mittel.
Dann prüf noch einmal. Hör auf, wenn eine Runde nichts Wichtiges mehr findet.

Probier das

Starte für die Prüfung eine neue Sitzung. Ein Prüfer, der den Code nicht selbst geschrieben hat, sieht mehr.

Schritt 5

Inhalte ohne Code ändern

Für einen neuen Link änderst du drei Zeilen.

Alle Texte, Links und Menüs meiner Seite stehen in public/config.json. So sieht mein Kontakt-Menü darin aus, gekürzt:

public/config.json · Auszug
{
  "label": "Instagram",
  "detail": "@anstatt.ai",
  "href": "https://www.instagram.com/anstatt.ai"
}

Für einen neuen Link kopiere ich so einen Block und ändere drei Zeilen. Seit Oktober kamen zwei Sprachen dazu, ein Spiele-Menü, meine Video-Anleitung und mein Angebot. Alle Menüpunkte stehen in dieser Datei. Snake, das Blockspiel und die Sprachumschaltung hat Claude Code dazugebaut.

Probier das

Lass Claude Code eine Anleitung schreiben, die jedes Feld der Datei erklärt. Meine liegt als README im Projekt.

Schritt 6

Gratis online stellen

GitHub Pages hostet die Seite ohne Monatsgebühr.

So geht's

  1. Leg ein kostenloses Konto auf github.com an.
  2. Leg ein öffentliches Repository an. Im Gratis-Plan läuft GitHub Pages nur mit öffentlichen Repositorys.
  3. Sag Claude Code: „Richte das Deployment auf GitHub Pages mit GitHub Actions ein.“
  4. Auf GitHub unter Settings → Pages bei Source „GitHub Actions“ wählen.
  5. Hochladen. Ein paar Minuten später ist die Seite unter deinname.github.io/repo online.

Achtung

Öffentlich heißt, jeder kann deinen Code lesen. Schreib also keine Passwörter oder Zugangsschlüssel hinein.

Quelle: GitHub Docs, About GitHub Pages, abgerufen am 4. November 2026.

Schritt 7

Eigene Domain

Optional. Eine Adresse, die man sich merkt.

Meine Seite läuft unter anstattpunkt.com. Die Domain kostet mich 16,99 $ im Jahr.

So geht's

  1. Kauf eine Domain bei einem Anbieter deiner Wahl.
  2. Trag sie auf GitHub unter Settings → Pages → Custom domain ein.
  3. Leg beim Anbieter in den DNS-Einstellungen vier A-Einträge für die Domain an: 185.199.108.153, 185.199.109.153, 185.199.110.153 und 185.199.111.153.
  4. Leg dazu einen CNAME-Eintrag für www an, der auf deinname.github.io zeigt.
  5. Warte, bis GitHub das Zertifikat ausstellt. Dann hak „Enforce HTTPS“ an.

Quelle: GitHub Docs, Managing a custom domain, abgerufen am 4. November 2026.

Zum Schluss

Rechtliches in Österreich und Deutschland

Kurz, aber wichtig. In Österreich gilt ein Teil davon für jede Website.

Impressum

In Österreich braucht jede Website eine Offenlegung nach § 25 Mediengesetz. Bei einer rein privaten Seite reichen Name und Wohnort. Bietest du etwas an, kommen die Angaben nach § 5 E-Commerce-Gesetz dazu. In Deutschland gilt für geschäftliche Seiten § 5 Digitale-Dienste-Gesetz.

Schriften

Leg Schriften als Dateien auf deine eigene Seite. Lädt die Seite sie bei Google, geht die IP-Adresse jedes Besuchers dorthin. Das Landgericht München hat das 2022 als Datenschutzverstoß gewertet.

Marken

Nimm keine fremden Logos als Deko. Mein iPod ist selbst gezeichnet. Der Name „iPod“ gehört Apple und steht bei mir nur, um zu beschreiben, was man sieht.

Das ist keine Rechtsberatung. Im Zweifel frag bei der Wirtschaftskammer oder der IHK nach.
